# 自动化测试规则

## 目录职责

- `unit/`: 验证单个类型、函数和组件。
- `integration/`: 验证模块协作、持久化和外部适配器边界。
- `security/`: 验证路径逃逸、权限绕过、危险输入、敏感信息和资源预算。

## 编写规则

- 测试文件使用 `test_<subject>.py`，测试名使用 `test_<behavior>_<condition>_<result>`。
- 新功能和缺陷修复同步增加或更新测试。
- 测试覆盖正常路径、边界条件、错误路径和安全约束。
- 单元测试使用 fake provider、临时时钟、临时目录和固定随机种子。
- 单元测试不访问真实网络、真实模型、用户目录和共享持久化数据。
- 集成测试对外部依赖、凭据和环境条件使用显式 marker。
- 测试断言可观察行为和稳定契约，避免绑定私有实现细节。
- 缺陷修复先形成可复现测试，再完成实现。
- 失败信息包含输入条件、预期行为和关键实际值。

## 执行规则

- 开发过程中先运行最小相关测试集。
- 跨模块、持久化或公共接口变化运行对应集成测试。
- 安全边界变化运行完整安全测试集。
- 交付前运行与改动风险相匹配的测试范围。
