# 文档规则

## 目录职责

- `plans/`: 路线图、阶段目标和开发计划。
- `tutorials/`: 经过整理、验证并可复现的学习教程。
- `design/`: 当前架构、接口、数据模型、威胁模型和关键流程。
- `design/adr/`: 影响长期实现的架构决策记录。

文档任务读取对应子目录中的相关文件。设计任务按需读取 `design/`，阶段规划按需读取 `plans/`。

## 通用写作规范

- 每份文档解决一个主要读者问题，并使用唯一的一级标题。
- 开头说明目标、适用范围和前置知识。
- 标题表达内容，段落首句给出结论，术语首次出现时定义。
- 操作步骤按执行顺序编号，命令注明运行目录、前置条件和预期结果。
- 代码块注明语言，示例保持最小、完整、可运行，并与当前接口同步。
- 内部链接使用相对路径；外部资料记录标题、发布方、URL 和访问日期。
- 版本、API 行为、安全规范和时效性信息引用当前官方来源。
- 图表用于解释结构、状态、时序或数据流，并与正文使用相同术语。
- 修改接口或 schema 时，同步更新设计、示例、测试和相关 ADR。

## 文档类型

按照 Diátaxis 明确每份文档的主要类型：

- Tutorial: 以学习为目标，引导读者完成一次成功实践。
- How-to: 以具体任务为目标，提供可直接执行的步骤。
- Reference: 准确描述接口、schema、配置和命令。
- Explanation: 解释概念、机制、约束和设计关系。

单篇文档保持一种主要类型。深入机制链接至 Explanation，完整参数链接至 Reference。

## 计划规范

- 计划包含目标、范围、输入、产出、依赖、风险、任务和完成条件。
- 阶段任务控制在一次学习或开发会话能够完成的粒度。
- 状态使用 `planned`、`in-progress`、`blocked`、`completed`。
- `completed` 状态附带代码、测试、评测或知识验收证据。

## 教程规范

- 教程结构为：学习目标、前置知识、核心概念、动手实现、运行验证、故障练习、掌握检查、延伸阅读。
- AI 生成的技术结论通过官方文档或可复现实验核验。
- 示例解释关键状态变化、失败路径和安全边界。
- 掌握检查验证解释、迁移和独立排障能力。

## 设计与 ADR 规范

- 设计文档说明目标、边界、组件职责、数据流、状态迁移、接口、失败语义、安全约束和验证方式。
- ADR 文件名使用 `NNNN-<decision-name>.md`，四位序号递增。
- ADR 包含背景、决策、约束、影响和验证方式。
