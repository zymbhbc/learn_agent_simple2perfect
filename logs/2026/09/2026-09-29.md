## 14:14｜理解 ToolCallingAgent 与 CodeAgent 的划分边界

- 目标: 判断 smolagents 的两类 Agent 划分是否适用于 Codex、OpenCode 和自研 AI 助手。
- 实际工作: 阅读 smolagents Guided Tour 中两类 Agent 的定义, 对照 OpenAI 官方 Codex Harness、Agent Loop 和 Shell Tool 文档, 分析结构化工具调用与代码执行之间的组合关系。
- 产出路径: `logs/2026/09/2026-09-29.md`。
- 验证证据: smolagents 官方文档将差异定义为动作表达与执行方式, 即 Python 代码动作和结构化 JSON 工具调用; OpenAI 官方文档说明 Codex Harness 通过工具循环调用函数工具、Shell 和沙箱执行环境。

## 14:45｜区分函数工具、MCP Tool 与 Skill Script

- 目标: 理解三类能力在模型上下文、调用协议和实际执行路径中的关系。
- 实际工作: 对照 smolagents Tool、MCP Tools 规范和 OpenAI Skills 文档, 拆分工具发现、上下文注入、动作生成、执行适配与结果回填过程。
- 产出路径: `logs/2026/09/2026-09-29.md`。
- 验证证据: smolagents `@tool` 将函数转换为带名称、描述和输入输出类型的 Tool; MCP 客户端通过 `tools/list` 获取 schema 并通过 `tools/call` 调用服务端工具; Skill 发现阶段只向模型提供名称、描述和路径, 完整 `SKILL.md` 与关联脚本按需读取和执行。
- 当前结论: 函数工具与 MCP Tool 都以结构化工具 schema 暴露给模型, 执行时分别进入本地函数适配器和 MCP 客户端; Skill 属于按需加载的工作流指令层, 其 script 是支持资源, 需要通过 Shell、Python Executor 或显式工具包装运行。
- 遗留问题: 自研 Harness 需要确定 Skill 元数据索引、按需加载协议以及脚本执行所采用的沙箱接口。
- 下一步: 阶段 2 的 Tool Registry 统一保存工具 schema, 并为本地函数与 MCP Tool 提供不同执行适配器; 阶段 5 将 Skill script 接入受控代码执行环境。

- 目标: 解释运行日志中 `assistant`、`tool-call` 和 `tool-response` 与常见 `system`、`user`、`assistant`、`tool` 角色的关系。

- 产出路径: `notes/Agent中工具如何使用.md`、`logs/2026/09/2026-09-29.md`。
- 验证证据: 日志中空 `assistant` 后依次出现包含调用 ID、名称和参数的 `tool-call`，以及包含 `Observation: 6` 的 `tool-response`; smolagents 1.26.0 定义五个内部 `MessageRole`; OpenAI 官方文档使用 `assistant.tool_calls` 与带 `tool_call_id` 的 `tool` 消息，Responses API 使用 `function_call` 与 `function_call_output` Item。
